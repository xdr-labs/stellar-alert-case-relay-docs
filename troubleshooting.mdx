## API token is required

With the wizard, enter a valid All-Access API token when prompted.

For manual CLI runs:

```bash
export STELLAR_TOKEN='YOUR_ALL_ACCESS_TOKEN'
```

## Stream configuration error

Each enabled stream requires its interval, destination IP, and destination port.

The relay also rejects invalid IP addresses, intervals below 1 second, ports outside `1-65535`, and configurations with no enabled stream.

See [Configuration](/configuration) for the full option reference.

## "Another instance is already running"

Check whether the systemd service or another foreground process is already running:

```bash
sudo systemctl status stellar-alert-case-syslog
ps -ef | grep '[S]tellar_Alert_Case_Syslog.py'
```

Do not remove the lock file while another relay process is running.

## systemd installation fails

The wizard needs sudo access to install the service. Run:

```bash
python3 Stellar_Alert_Case_Syslog.py --setup
```

and enter the sudo password when requested.

## Service is not running

```bash
sudo systemctl status stellar-alert-case-syslog
sudo journalctl -u stellar-alert-case-syslog -n 50 --no-pager
```

## Service is active but no records arrive

Check the journal first:

```bash
sudo journalctl -u stellar-alert-case-syslog -f
```

Then verify:

1. Stellar Cyber host, User ID, and API token
2. Alert/Case interval and destination
3. TCP reachability to the receiver
4. Receiver parsing for one JSON object per line

## Receiver is unreachable

Unsent records remain in the SQLite queue and are retried. Restore the receiver/network path and follow the journal for recovery.

## Receiver cannot parse records

The relay sends NDJSON over TCP:

```text
JSON object + newline
JSON object + newline
```

Configure the receiver for line-delimited JSON rather than RFC syslog framing.

## More diagnostics

Run manually with `--debug` when detailed fetch/enqueue/send diagnostics are needed:

```bash
python3 Stellar_Alert_Case_Syslog.py ... --debug
```
