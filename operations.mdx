## Install

Run the setup wizard:

```bash
python3 Stellar_Alert_Case_Syslog.py --setup
```

After configuration, answer **Yes** to:

```text
Run continuously with systemd (auto-start on boot)?
```

The wizard installs, enables, and starts `stellar-alert-case-syslog.service`. Sudo access is required.

## Common commands

### Status

```bash
sudo systemctl status stellar-alert-case-syslog
```

### Follow logs

```bash
sudo journalctl -u stellar-alert-case-syslog -f
```

### Recent logs

```bash
sudo journalctl -u stellar-alert-case-syslog -n 50 --no-pager
```

### Restart

```bash
sudo systemctl restart stellar-alert-case-syslog
```

### Confirm boot startup

```bash
systemctl is-enabled stellar-alert-case-syslog
```

<Note>
An active service confirms that the process is running. Check the journal to confirm Stellar API fetch and TCP delivery.
</Note>

## Reconfigure

Run the wizard again and choose systemd installation:

```bash
python3 Stellar_Alert_Case_Syslog.py --setup
```

The installed configuration is replaced and the service is restarted.

## Installed files

```text
/usr/local/lib/stellar-alert-case/Stellar_Alert_Case_Syslog.py
/etc/default/stellar-alert-case-syslog
/etc/systemd/system/stellar-alert-case-syslog.service
```

The API token is stored in the protected environment file, not in the systemd command line.

<Warning>
Do not copy the contents of `/etc/default/stellar-alert-case-syslog` into support tickets or shared logs.
</Warning>

## Persistent state

By default, queue/checkpoint data and logs are stored under:

```text
~/.local/state/stellar_alert_case/
```

If a TCP receiver becomes unavailable, unsent data remains queued for retry.
