새로 설치할 때는 **처음부터 systemd로 등록하지 않고 foreground에서 먼저 실제 전송을 검증하는 것을 권장합니다.** Alert와 Case가 정상적으로 전달되는 것을 확인한 뒤, 마지막에 Setup Wizard를 한 번 실행해 검증된 설정을 systemd 서비스로 운영합니다.

이 방식이면 API 또는 수신기 설정이 잘못된 상태에서 서비스를 먼저 설치하는 일을 피할 수 있습니다.

## 1. 스크립트 다운로드

```bash
curl -fL \
  -o Stellar_Alert_Case_Syslog.py \
  https://raw.githubusercontent.com/xdr-labs/Stellar-Case-Alert-to-Sylog/main/Stellar_Alert_Case_Syslog.py
```

필요한 환경:

- Python 3
- Stellar Cyber API로의 네트워크 연결
- 대상 TCP listener로의 네트워크 연결
- Stellar Cyber User ID와 All-Access API token
- 최종 운영 전환 시 Linux + systemd

아래 예제의 수신기 IP와 port는 실제 환경의 값으로 변경하십시오.

## 2. 테스트용 API token 설정

Foreground 테스트에서는 token을 명령행에 직접 넣지 않고 `STELLAR_TOKEN`을 사용합니다.

```bash
export STELLAR_TOKEN='YOUR_ALL_ACCESS_TOKEN'
```

## 3. Alert만 먼저 테스트

가장 단순한 경로부터 확인합니다. 이 단계에서는 **Wizard와 systemd를 사용하지 않습니다.**

```bash
python3 Stellar_Alert_Case_Syslog.py \
  --alert-interval 60 \
  --alert-syslog-ip 10.10.10.20 \
  --alert-syslog-port 5201 \
  --debug
```

다음을 확인합니다.

- 인증/API 오류 없이 프로세스가 시작되는지
- 설정한 TCP 수신기로 Alert가 들어오는지
- 수신 데이터가 한 줄당 JSON 객체 하나로 들어오는지

몇 번의 fetch cycle 동안 정상 동작하는 것을 확인한 뒤 **Ctrl+C**로 종료합니다.

<Note>
운영에서도 Alert만 사용할 예정이라면 이 테스트가 성공한 뒤 Alert+Case 동시 테스트는 건너뛰고 최종 운영 설정으로 넘어가도 됩니다.
</Note>

## 4. Alert와 Case를 함께 테스트

운영에서 두 스트림을 모두 사용할 경우 systemd 설치 전에 함께 실행해 봅니다.

```bash
python3 Stellar_Alert_Case_Syslog.py \
  --alert-interval 60 \
  --alert-syslog-ip 10.10.10.20 \
  --alert-syslog-port 5201 \
  --case-interval 300 \
  --case-syslog-ip 10.10.10.20 \
  --case-syslog-port 5202 \
  --debug
```

Alert와 Case가 각각 설정한 수신기로 정상 전달되는지 확인합니다.

두 스트림은 같은 수신기를 사용해도 되고 서로 다른 IP/port를 사용해도 됩니다.

정상 전달을 확인했으면 **Ctrl+C**로 foreground 프로세스를 종료합니다.

## 5. 검증된 설정을 운영으로 전환

이제 Setup Wizard를 실행합니다.

```bash
python3 Stellar_Alert_Case_Syslog.py --setup
```

앞의 foreground 테스트에서 **실제로 정상 동작한 값**을 그대로 입력합니다.

1. Stellar Cyber host
2. User ID
3. All-Access API token
4. Alert 활성화 여부
5. Case 활성화 여부
6. 각 스트림에서 검증한 interval과 destination
7. Initial lookback

마지막 질문:

```text
Run continuously with systemd (auto-start on boot)?
```

에서는 **Yes**를 선택합니다.

Wizard가 `stellar-alert-case-syslog.service`를 설치하고, 부팅 자동 시작을 활성화하고, 즉시 서비스를 시작한 뒤 상태와 최근 로그를 보여줍니다.

## 6. 운영 서비스 확인

서비스가 실행 중이고 부팅 시 자동 시작되도록 설정됐는지 확인합니다.

```bash
sudo systemctl status stellar-alert-case-syslog
systemctl is-enabled stellar-alert-case-syslog
```

최근 로그도 확인합니다.

```bash
sudo journalctl -u stellar-alert-case-syslog -n 20 --no-pager
```

반복되는 API/인증/TCP 전송 오류가 없고 수신기에도 데이터가 계속 들어오면 운영 전환이 완료된 것입니다.

## 7. 운영 중에는 로그만 확인

평상시에는 대부분 journal만 확인하면 됩니다.

### 실시간 로그 보기

```bash
sudo journalctl -u stellar-alert-case-syslog -f
```

로그 확인을 끝낼 때는 **Ctrl+C**를 누릅니다. 서비스 자체는 종료되지 않습니다.

### 최근 로그 50줄 확인

```bash
sudo journalctl -u stellar-alert-case-syslog -n 50 --no-pager
```

### 오늘 로그 전체 확인

```bash
sudo journalctl -u stellar-alert-case-syslog --since today --no-pager
```

서비스가 active이고 journal에서 정상적인 fetch/send가 계속 보이며 반복 오류가 없다면 일반적으로 추가 작업은 필요하지 않습니다.

## 권장 배포 순서

```text
스크립트 다운로드
      |
      v
Foreground Alert 테스트
      |
      v
Foreground Alert + Case 테스트 (Case 사용 시)
      |
      v
검증된 값을 Setup Wizard에 입력
      |
      v
systemd 활성화
      |
      v
운영 중 journal 확인
```
