# Troubleshooting

## Service가 시작되지 않음

```bash
sudo systemctl status stellar-alert-case-syslog
sudo journalctl -u stellar-alert-case-syslog -n 100 --no-pager
```

설정이 잘못되었다면 Wizard를 다시 실행합니다.

```bash
python3 Stellar_Alert_Case_Syslog.py --setup
```

## API 인증 실패

확인 항목:

- Stellar Host / User ID
- All-Access API Token 유효성
- Outbound HTTPS 연결
- systemd 실행 시 Token Environment File

Wizard/Service는 `STELLAR_TOKEN`을 사용합니다. Token을 Script에 hard-code하지 마십시오.

## Alert 또는 Case가 들어오지 않음

사용할 Stream에 다음 세 값이 모두 있는지 확인합니다.

```text
interval
destination IP
destination port
```

First-run Lookback과 Stellar 측 실제 Data 존재 여부도 확인합니다.

## Receiver에 Data가 오지 않음

TCP 연결 확인:

```bash
nc -vz <DESTINATION_IP> <PORT>
```

Receiver가 RFC Syslog가 아니라 **NDJSON over TCP**를 받도록 설정되어 있는지도 확인합니다.

Receiver가 Down이면 Record는 SQLite Queue에 Pending 상태로 남고 재시도됩니다.

## Another instance is already running

같은 State/Lock Path는 한 Process만 사용해야 합니다.

Lock file을 삭제하기 전에 기존 Service/Process를 확인합니다.

```bash
sudo systemctl status stellar-alert-case-syslog
ps -ef | grep Stellar_Alert_Case_Syslog.py
```

## JSON Parsing 실패

Receiver는 LF로 끝나는 각 Line을 하나의 JSON object로 parse해야 합니다.

## Backfill 중 Duplicate 발생

정상 동작입니다. `--backfill DAYS`는 normal checkpoint를 무시하므로 historical record를 다시 보낼 수 있습니다.
