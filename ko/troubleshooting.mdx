# Troubleshooting

## 서비스가 시작되지 않음

```bash
sudo systemctl status stellar-alert-case-syslog
sudo journalctl -u stellar-alert-case-syslog -n 100 --no-pager
```

설정이 잘못되었다면 Wizard를 다시 실행합니다.

```bash
python3 Stellar_Alert_Case_Syslog.py --setup
```

## API 인증 실패

확인 항목:

- Stellar Host / User ID
- All-Access API 토큰 유효성
- Outbound HTTPS 연결
- systemd 실행 시 토큰 환경 파일

Wizard/Service는 `STELLAR_TOKEN`을 사용합니다. 토큰을 스크립트에 직접 입력하지 마십시오.

## Alert 또는 Case가 들어오지 않음

사용할 Alert/Case 유형에 다음 세 값이 모두 있는지 확인합니다.

```text
interval
destination IP
destination port
```

최초 조회 범위와 Stellar 측 실제 데이터 존재 여부도 확인합니다.

## 수신기에 데이터가 오지 않음

TCP 연결 확인:

```bash
nc -vz <DESTINATION_IP> <PORT>
```

수신기가 RFC Syslog가 아니라 **NDJSON over TCP**를 받도록 설정되어 있는지도 확인합니다.

수신기가 중단되면 데이터는 SQLite 큐에 대기 상태로 남고 재시도됩니다.

## Another instance is already running

같은 상태/잠금 경로는 한 프로세스만 사용해야 합니다.

잠금 파일을 삭제하기 전에 기존 서비스/프로세스를 확인합니다.

```bash
sudo systemctl status stellar-alert-case-syslog
ps -ef | grep Stellar_Alert_Case_Syslog.py
```

## JSON Parsing 실패

수신기는 LF로 끝나는 각 줄을 하나의 JSON 객체로 처리해야 합니다.

## Backfill 중 중복 데이터 발생

정상 동작입니다. `--backfill DAYS`는 일반 체크포인트를 무시하므로 과거 데이터를 다시 보낼 수 있습니다.
