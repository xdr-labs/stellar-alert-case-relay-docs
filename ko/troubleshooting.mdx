## API token 오류

Wizard에서는 유효한 All-Access API token을 입력합니다.

수동 CLI에서는:

```bash
export STELLAR_TOKEN='YOUR_ALL_ACCESS_TOKEN'
```

## 스트림 설정 오류

활성화한 각 스트림에는 interval, destination IP, destination port가 모두 필요합니다.

잘못된 IP, 1초 미만 interval, `1-65535` 범위를 벗어난 port, Alert/Case 모두 비활성화된 설정도 거부됩니다.

전체 옵션은 [설정](/ko/configuration)을 참고하십시오.

## "Another instance is already running"

기존 systemd 서비스 또는 foreground 프로세스를 확인합니다.

```bash
sudo systemctl status stellar-alert-case-syslog
ps -ef | grep '[S]tellar_Alert_Case_Syslog.py'
```

다른 Relay 프로세스가 실행 중일 때 lock 파일부터 삭제하지 마십시오.

## systemd 설치 실패

Wizard는 sudo 권한이 필요합니다.

```bash
python3 Stellar_Alert_Case_Syslog.py --setup
```

필요한 경우 sudo 비밀번호를 입력합니다.

## 서비스가 실행되지 않음

```bash
sudo systemctl status stellar-alert-case-syslog
sudo journalctl -u stellar-alert-case-syslog -n 50 --no-pager
```

## 서비스는 active인데 데이터가 오지 않음

먼저 journal을 확인합니다.

```bash
sudo journalctl -u stellar-alert-case-syslog -f
```

다음을 순서대로 확인하십시오.

1. Stellar Cyber host, User ID, API token
2. Alert/Case interval과 destination
3. 수신기까지 TCP 연결
4. 수신기가 한 줄당 JSON 객체 하나를 처리하는지 여부

## 수신기가 내려감

미전송 데이터는 SQLite queue에 남아 재시도됩니다. 수신기 또는 네트워크를 복구한 뒤 journal에서 복구 상태를 확인하십시오.

## JSON parsing 문제

Relay는 TCP NDJSON을 전송합니다.

```text
JSON object + newline
JSON object + newline
```

수신기는 RFC Syslog가 아니라 line-delimited JSON으로 구성해야 합니다.

## 추가 진단

상세 fetch/enqueue/send 로그가 필요할 때 수동 실행에 `--debug`를 추가합니다.

```bash
python3 Stellar_Alert_Case_Syslog.py ... --debug
```
