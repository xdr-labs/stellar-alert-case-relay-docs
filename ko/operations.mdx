## 설치

Setup Wizard를 실행합니다.

```bash
python3 Stellar_Alert_Case_Syslog.py --setup
```

설정이 끝난 뒤 다음 질문에 **Yes**를 선택합니다.

```text
Run continuously with systemd (auto-start on boot)?
```

Wizard가 `stellar-alert-case-syslog.service`를 설치·활성화·시작합니다. sudo 권한이 필요합니다.

## 주요 운영 명령

### 상태 확인

```bash
sudo systemctl status stellar-alert-case-syslog
```

### 실시간 로그

```bash
sudo journalctl -u stellar-alert-case-syslog -f
```

### 최근 로그

```bash
sudo journalctl -u stellar-alert-case-syslog -n 50 --no-pager
```

### 재시작

```bash
sudo systemctl restart stellar-alert-case-syslog
```

### 부팅 자동 시작 확인

```bash
systemctl is-enabled stellar-alert-case-syslog
```

<Note>
서비스가 active라는 것은 프로세스가 실행 중이라는 뜻입니다. Stellar API fetch와 TCP 전달 성공 여부는 journal에서도 확인하십시오.
</Note>

## 설정 변경

Wizard를 다시 실행하고 systemd 설치를 선택합니다.

```bash
python3 Stellar_Alert_Case_Syslog.py --setup
```

새 설정이 적용되고 서비스가 재시작됩니다.

## 설치 파일

```text
/usr/local/lib/stellar-alert-case/Stellar_Alert_Case_Syslog.py
/etc/default/stellar-alert-case-syslog
/etc/systemd/system/stellar-alert-case-syslog.service
```

API token은 systemd 명령행이 아니라 보호된 environment file에 저장됩니다.

<Warning>
`/etc/default/stellar-alert-case-syslog`의 내용을 지원 티켓이나 공유 로그에 그대로 복사하지 마십시오.
</Warning>

## 상태 데이터

기본 queue/checkpoint와 로그는 다음 경로에 저장됩니다.

```text
~/.local/state/stellar_alert_case/
```

TCP 수신기가 일시적으로 내려가면 미전송 데이터는 queue에 남아 재시도됩니다.
