Wizard 버전 Relay는 systemd 서비스를 직접 생성하고 활성화할 수 있습니다. 수동으로 unit 파일을 작성하는 방식은 더 이상 권장 설치 경로가 아닙니다.

## Wizard에서 설치

다음을 실행합니다.

```bash
python3 Stellar_Alert_Case_Syslog.py --setup
```

Alert/Case 설정을 완료한 뒤 다음 질문에 **Yes**를 선택합니다.

```text
Run continuously with systemd (auto-start on boot)?
```

관리자 권한이 필요합니다. 현재 shell이 root가 아니면 스크립트가 sudo를 실행하며 비밀번호를 요청할 수 있습니다.

## 설치되는 파일

Wizard는 다음 파일을 생성하거나 교체합니다.

```text
/usr/local/lib/stellar-alert-case/Stellar_Alert_Case_Syslog.py
/etc/default/stellar-alert-case-syslog
/etc/systemd/system/stellar-alert-case-syslog.service
```

Token 환경파일은 `0600` 권한으로 생성됩니다.

생성되는 서비스는 Wizard를 실행한 사용자의 계정과 HOME을 사용하므로 기본 SQLite/log 경로도 그 사용자 기준으로 유지됩니다.

서비스에는 다음 설정이 포함됩니다.

```ini
Restart=always
RestartSec=5
UMask=0077
```

API token은 다음 EnvironmentFile로 읽습니다.

```ini
EnvironmentFile=-/etc/default/stellar-alert-case-syslog
```

따라서 token이 `ExecStart` 명령행에 포함되지 않습니다.

## 자동으로 수행되는 작업

설치 과정은 다음 systemd 작업을 수행합니다.

```bash
sudo systemctl daemon-reload
sudo systemctl enable stellar-alert-case-syslog
sudo systemctl restart stellar-alert-case-syslog
```

그 후 자동으로:

- 전체 service status 출력
- 최근 journal 20줄 출력
- active 상태 확인
- enabled 상태 확인

을 수행합니다.

## 상태 확인

```bash
sudo systemctl status stellar-alert-case-syslog
```

실행 상태와 부팅 자동 시작 상태를 각각 확인하려면:

```bash
systemctl is-active stellar-alert-case-syslog
systemctl is-enabled stellar-alert-case-syslog
```

## 로그 확인

실시간:

```bash
sudo journalctl -u stellar-alert-case-syslog -f
```

최근 로그:

```bash
sudo journalctl -u stellar-alert-case-syslog -n 50 --no-pager
```

서비스가 active라고 해서 Stellar API fetch와 TCP 전달까지 성공했다는 의미는 아닙니다. 설치 후 journal에서 실제 fetch/send 로그도 확인하십시오.

## 서비스 재시작

```bash
sudo systemctl restart stellar-alert-case-syslog
sudo systemctl status stellar-alert-case-syslog
```

## 설정 변경

Wizard를 다시 실행합니다.

```bash
python3 Stellar_Alert_Case_Syslog.py --setup
```

새 설정을 입력하고 systemd 설치에 **Yes**를 선택하면 설치 스크립트와 설정을 교체하고 systemd를 reload한 뒤 서비스를 restart합니다.

## 설치된 Unit 확인

```bash
systemctl cat stellar-alert-case-syslog
```

<Warning>
`/etc/default/stellar-alert-case-syslog`에는 API credential이 들어 있습니다. 지원 로그나 공개 문서에 파일 내용을 그대로 복사하지 마십시오.
</Warning>

## 런타임 상태

서비스는 Wizard를 실행한 사용자의 HOME을 사용하므로 기본 상태 데이터는 다음에 유지됩니다.

```text
~/.local/state/stellar_alert_case/
```

여기에는 SQLite queue/checkpoint, process lock, relay log가 포함됩니다.

## TCP 수신기 장애

목적지 TCP listener가 내려가면 미전송 데이터는 SQLite queue에 남고 Relay는 retry/recovery 경로로 전환됩니다. 전송에 실패한 row를 sent로 처리하지 않습니다.
