Relay는 대화형 설정 마법사와 CLI 인터페이스를 모두 지원합니다.

## 인증 및 공통 옵션

| 옵션 | 용도 |
| --- | --- |
| `--setup` | 대화형 설정/systemd 설치 Wizard 실행 |
| `--host` | Stellar Cyber host |
| `--userid` | Stellar Cyber User ID (이메일 형식) |
| `--token` | All-Access API 토큰 |
| `STELLAR_TOKEN` | API 토큰을 전달하는 권장 환경변수 |
| `--initial-lookback-hours` | checkpoint가 없는 최초 실행의 조회 범위. `0`은 1분 범위이며 Alert는 stability cutoff를 기준으로 계산 |
| `--backfill DAYS` | 정상 checkpoint를 무시하고 매 주기마다 최근 N일 데이터를 다시 조회·전송 |
| `--db-path` | SQLite 큐/체크포인트 DB 경로 |
| `--log-dir` | 전송/조회 로그 디렉터리 |
| `--lock-path` | 단일 프로세스 실행을 위한 lock 파일 |
| `--send-log-retention-days` | 전송 요약 로그 보존 일수 |
| `--debug` | fetch/enqueue/send 진단 로그를 stderr에 출력 |

<Note>
수동 실행에서는 token을 명령행에 직접 넣는 것보다 `STELLAR_TOKEN` 환경변수를 사용하는 것을 권장합니다.
</Note>

## Alert 스트림

| 옵션 | 용도 | 기본값/예제 |
| --- | --- | --- |
| `--alert-interval SEC` | Alert 조회/전송 주기 | Wizard 기본값 `60` |
| `--alert-syslog-ip IP` | Alert 목적지 IPv4/IPv6 주소 | 활성화 시 필수 |
| `--alert-syslog-port PORT` | Alert 목적지 TCP 포트 | Wizard 기본값 `5201` |
| `--alert-fetch-stability-lag-sec SEC` | 증분 Alert fetch의 조회 종료 시점에 적용하는 안정화 지연 시간 | `120` |
| `--alert-sent-retention-minutes` | 전송 완료 Alert 큐 항목 보존 시간 | `10` |

Alert 스트림을 활성화하려면 interval, IP, port 세 옵션을 모두 지정해야 합니다.

## Case 스트림

| 옵션 | 용도 | 기본값/예제 |
| --- | --- | --- |
| `--case-interval SEC` | Case 조회/전송 주기 | Wizard 기본값 `300` |
| `--case-syslog-ip IP` | Case 목적지 IPv4/IPv6 주소 | 활성화 시 필수 |
| `--case-syslog-port PORT` | Case 목적지 TCP 포트 | Wizard 기본값 `5202` |
| `--case-min-score` | 전달할 Case 최소 점수 | `10` |
| `--case-include-summary` / `--no-case-include-summary` | Case 요약 포함/제외 | enabled |
| `--case-format-summary` / `--no-case-format-summary` | Case 요약 형식 적용/해제 | enabled |
| `--case-fetch-limit` | Case API fetch page limit | `200` |


## 스트림 설정 규칙

<Steps>
  <Step title="스트림 옵션을 모두 생략">
    해당 스트림은 비활성화됩니다.
  </Step>
  <Step title="일부만 설정">
    필수 옵션 중 하나라도 지정했다면 interval, IP, port 세 가지를 모두 제공해야 합니다.
  </Step>
  <Step title="입력 검증">
    주기는 1 이상이어야 하고, 목적지는 유효한 IPv4/IPv6 주소여야 하며, 포트는 1~65535 범위여야 합니다.
  </Step>
  <Step title="최소 하나의 스트림">
    Alert, Case 또는 둘 다 완전하게 구성되어야 합니다.
  </Step>
</Steps>

## 상태 저장

기본 런타임 상태는 다음 경로에 저장됩니다.

```text
~/.local/state/stellar_alert_case/
├── queue.db
├── stellar_alert_case.lock
└── logs/
```

SQLite DB에는 큐와 체크포인트가 저장되므로 프로세스가 재시작되어도 상태가 유지됩니다. TCP 수신기가 내려간 경우 전송되지 않은 항목도 보존됩니다.

## Backfill

`--backfill DAYS`는 과거 데이터 재전송 모드입니다. 지정한 기간을 매 주기마다 다시 조회·전송하고 일반 체크포인트를 무시합니다.

동일 기간의 레코드를 다시 전송할 수 있으므로 의도적으로 사용할 때만 활성화하십시오.

## Debug 모드

```bash
python3 Stellar_Alert_Case_Syslog.py ... --debug
```

문제 해결에 필요한 동안만 사용하고 진단이 끝나면 해제하는 것을 권장합니다.

<Info>
옵션 이름에는 `syslog`가 포함되어 있지만 실제 payload는 TCP 기반 newline-delimited JSON(NDJSON)입니다.
</Info>
