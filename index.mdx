Stellar Alert & Case Relay is a lightweight Python daemon for environments that already operate a SIEM or SOC portal and want Stellar Cyber detections delivered into those existing workflows.

<Info>
The original operational guide calls the script **Stellar Alert + Case Syslog Daemon**. Its documented wire format is **newline-delimited JSON (NDJSON) over TCP**, so this documentation uses the broader product name **Stellar Alert & Case Relay**.
</Info>

## Why it exists

Many on-prem SOC teams already have established SIEM dashboards, monitoring portals, and operational processes. They still need Stellar Cyber NDR/XDR alerts and cases inside those systems without relying on manual export or one-off integration work.

The relay provides a simple bridge:

```text
Stellar Cyber API
       |
       v
Python Relay Daemon
       |
       v
Customer SIEM / SOC Portal
```

## What it does

<CardGroup cols={2}>
  <Card title="Alert and case forwarding" icon="arrow-right-arrow-left">
    Pulls alerts and cases from the Stellar Cyber API and forwards them to downstream SOC systems.
  </Card>
  <Card title="Flexible stream modes" icon="sliders">
    Run alert-only, case-only, or both streams at the same time.
  </Card>
  <Card title="Operations-oriented delivery" icon="rotate">
    The operational guide identifies fetch checkpointing, send retry/recovery, and backfill as built-in capabilities.
  </Card>
  <Card title="Separate destinations" icon="route">
    Alert and case streams can use independent destination IP addresses and ports.
  </Card>
</CardGroup>

## At a glance

| Item | Documented behavior |
| --- | --- |
| Source | Stellar Cyber API |
| Runtime | Python daemon |
| Transport | TCP |
| Payload framing | NDJSON, one JSON object per line |
| Stream modes | Alert-only, case-only, or both |
| Alert destination | Independent IP and TCP port |
| Case destination | Independent IP and TCP port |
| Operational features | Fetch checkpoint, retry/recovery, backfill, separate destinations |

## Typical deployment

A common deployment runs the script continuously under `systemd` on a Linux host with network access to both the Stellar Cyber API and the destination SIEM/SOC receiver.

<Note>
The current source material does not specify the exact API authentication bootstrap, checkpoint file/storage format, retry algorithm, backfill controls, or emitted JSON schema. Those details should be verified against the runtime source before being documented as implementation guarantees.
</Note>
