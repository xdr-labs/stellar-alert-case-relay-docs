title: "Output format"
description: "TCP/NDJSON framing and receiver requirements."
---

The relay sends **newline-delimited JSON (NDJSON) over TCP**.

<Info>
The CLI uses historical option names such as `--alert-syslog-ip`, but the payload is not RFC 3164/5424 syslog.
</Info>

## Framing

Each line is one JSON object:

```text
{"...":"..."}\n
{"...":"..."}\n
```

The receiver must treat each newline as a record boundary.

## Destinations

Alert and Case streams use independent destination settings:

```text
Alert: --alert-syslog-ip + --alert-syslog-port
Case:  --case-syslog-ip  + --case-syslog-port
```

They may point to separate listeners or the same downstream system.

## Receiver checklist

Before production use, verify that:

- The TCP listener is reachable from the relay host.
- Each line is parsed as one JSON object.
- Alert and Case samples are routed correctly.
- SIEM timestamp, source type, and field mappings match actual relay output.

Capture representative events from your deployed version before finalizing the production parser.
